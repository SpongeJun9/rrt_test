# 01 环境安装与编译

## 目标平台

机器人 Ubuntu 22.04 / ROS 2 Humble。Windows 用于编辑和 Git 上传，不在 Windows 直接运行本工程节点。源码包含 amd64、arm64 预编译 SDK 库，需与机器人架构匹配。

使用纯英文的工作空间路径，例如 `/home/lionheart/rrt_test`。2026-10-18 实机验证发现：Humble 的 rosidl_adapter 使用不带 UTF-8 编码选项的 CMake `file(STRINGS)`，会截断 `桌面` 这样的中文路径，导致 Livox 消息生成报错。英文目录下构建通过；不要移动已有 build/install 直接复用到新位置。

先通过 ROS 官方方法安装 Humble 并确认 `/opt/ros/humble/setup.bash` 存在，然后安装构建工具：

```bash
sudo apt update
sudo apt install git git-lfs python3-colcon-common-extensions python3-rosdep \
  python3-numpy python3-yaml libeigen3-dev libomp-dev
```

仅当 rosdep 尚未初始化时运行 `sudo rosdep init`；已初始化不重复操作。随后：

```bash
rosdep update
git lfs install
git clone https://github.com/SpongeJun9/rrt_test.git
cd rrt_test
git lfs pull
git lfs fsck
```

地图 PCD 开头不应是 `version https://git-lfs.github.com/spec/v1`，否则它仍是指针，需要完成 `git lfs pull`。

## 构建两个工作区

```bash
cd ~/rrt_test  # 改为实际克隆目录
bash scripts/build_workspace.sh --install-deps
```

根目录脚本先从 `src/` 构建导航、模型、串口、PCD 转图及其依赖，再以根目录 `install/setup.bash` 为 underlay 构建独立 RAG 工作区。首次依赖安装可能需要 sudo。后续已安装依赖时：

```bash
bash scripts/build_workspace.sh
```

默认构建导航验证所需的依赖闭包，不构建所有视觉和仿真应用；它们的源码仍完整上传。若确实需要全部包：

```bash
source /opt/ros/humble/setup.bash
colcon build --base-paths src --symlink-install \
  --cmake-args -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=OFF
```

全包构建可能额外要求 Gazebo、相机、自瞄消息等依赖。不要以导航闭包构建通过代替完整工作区构建通过。若 rosdep 或 colcon 报错，保留完整输出，按第 6 份指南定位。

导航与 RAG 两个工作区已在 Ubuntu 22.04 / Humble x86_64 实机完成编译（21+3 个包）；不代表所有视觉和仿真包通过。根构建脚本默认使用 2 个并行包、每包 2 个构建任务，可按内存情况设置 `SENTRY_BUILD_WORKERS`、`CMAKE_BUILD_PARALLEL_LEVEL`、`MAKEFLAGS`。

`small_gicp_relocalization/CMakeLists.txt` 使用 FetchContent 从 GitHub `master` 获取 small_gicp，首次编译需要网络；尚未冻结到提交，论文部署时应记录实际编译版本。Livox SDK 和海康 SDK 的已有 `.so` 已随源码上传，但其 ABI、运行库及硬件兼容性需实机确认。

## 每个手动操作终端

根目录脚本会自动加载环境。若手动运行 `ros2` 命令，每个新终端执行：

```bash
source /opt/ros/humble/setup.bash
source ~/rrt_test/install/setup.bash  # 替换目录
```

RAG 单独脚本还需要：

```bash
export SENTRY_UNDERLAY_SETUP="$HOME/rrt_test/install/setup.bash"
```

构建完成后先进入第 2 份指南建图，或使用已确认匹配场地的地图进入第 3 份指南。

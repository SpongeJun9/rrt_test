# 02 建图与地图保存

## 输出文件

每个场地保存同一次采集产生的三件文件：`test_site.yaml`、YAML 引用的图像（通常 `test_site.pgm`）、`test_site.pcd`。二维地图给 RAG 规划，PCD 给 small_gicp 重定位。不能混用不同采集轮次的文件或独自修改地图原点。

## 启动与采集

先结束导航验证入口，避免两套程序同时占用雷达、TF、串口和 `/map`。

```bash
cd ~/rrt_test
mkdir -p ~/sentry_maps/test_site
bash scripts/start_mapping.sh
```

此脚本调用原实车 `slam:=True` 启动入口：雷达、Point-LIO、地形分析、扫描转换、slam_toolbox 和模型 TF；small_gicp 不启动，`map → odom` 为静态单位变换。原启动文件同时包含 Nav2 和手柄节点，建图期间不要使用导航目标工具；由原遥控方式移动车辆。

如果已有独立的正确机器人模型 TF 发布器：

```bash
bash scripts/start_mapping.sh use_robot_state_pub:=False
```

若需要上位机串口控制底盘，在另一个已加载 ROS 环境的终端运行：

```bash
ros2 launch core_serial core_serial_bringup.launch.py
```

若遥控器可独立控制底盘，采集点云本身无需串口发送导航速度。先静止初始化，随后缓慢扫描场地外围、内部障碍、通道和转角，尽量回到起点附近。避免急转、自旋和活动人员遮挡。RViz 固定坐标系用 `map`，确认地图障碍连续、点云墙面没有明显重影。

本代码实际使用 `point_lio` 的重力、IMU 外参和原模型安装外参，不能套用别人的车。发现整幅点云倾斜或墙面重影，应先修正定位/外参，而不是直接用坏地图试验。

## 先保存二维图

建图进程保持运行，新终端加载原工作区环境后：

```bash
ros2 run nav2_map_server map_saver_cli \
  -f "$HOME/sentry_maps/test_site/test_site"
ls -lh ~/sentry_maps/test_site
cat ~/sentry_maps/test_site/test_site.yaml
```

本脚本默认无命名空间。若自行改变命名空间，保存命令的 `/map` 也必须匹配。

## 再正常退出并取回 PCD

二维图保存成功后，在建图终端按 Ctrl+C，等待 Point-LIO 正常完成退出。其源码在程序退出时写入编译时源码目录中的 `point_lio/PCD/scans.pcd`，不是当前 shell 目录或安装目录。

对于在本仓库构建的程序，通常是：

```bash
ls -lh src/pb2025_sentry_nav-main/point_lio/PCD/scans.pcd
cp src/pb2025_sentry_nav-main/point_lio/PCD/scans.pcd \
  ~/sentry_maps/test_site/test_site.pcd
```

检查修改时间、大小和运行日志，确认是本轮文件；已有 `scans.pcd` 可能是旧图。默认保存间隔为 `-1`，整个累积云在退出时写出；若改为正间隔，可能产生 `scans_N.pcd` 分片，不能只取最后残余文件当完整地图。不要通过 kill -9 结束 Point-LIO。

## 地图验收

```text
~/sentry_maps/test_site/
  test_site.yaml
  test_site.pgm   # 以 YAML 的 image 字段为准
  test_site.pcd
```

检查墙体/通道与实际场地一致、地图尺度正确、PCD 与二维图可对齐，再进入定位检查。现有 `pcd2pgm` 与重定位源码的坐标变换处理不同，不使用默认参数直接替换在线地图；若需转换，应单独核对变换方向和过滤高度。

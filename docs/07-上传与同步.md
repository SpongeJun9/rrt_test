# 07 上传与同步

## 当前仓库结构

原 `src/` 的 14 个嵌套仓库以普通源码文件上传，而不是 Git 子模块引用。它们本地的 `.git` 保持原样；上传脚本既不移动也不删除这些目录。GitHub 克隆得到完整源码快照，无需访问各上游账号。

由于 `git add .` 可能把嵌套仓库作为 gitlink 或跳过目录内文件，本工作空间统一使用 `scripts/stage_workspace.py`。它枚举实际源码，通过 Git clean filter（包括 LFS）写入对象并更新索引，最后拒绝残留的 gitlink。

PCD 和 ZIP 使用 LFS。普通 Git 文件超过 100 MiB 会被 GitHub 拒绝，见 [GitHub 文件限制](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github)；LFS 下载见 [Git LFS 说明](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-git-large-file-storage)。上传会使用账号的 LFS 存储/传输配额；脚本不购买服务或更改计费设置。

## Windows 每次上传

在 PowerShell：

```powershell
Set-Location 'G:\LionHeart\sentery'
git lfs install --local
git status --short

# 可选：仅看将收集多少文件
py -3.12 scripts/stage_workspace.py --check

# 暂存完整工作空间源码
py -3.12 scripts/stage_workspace.py
git diff --cached --stat
git diff --cached --name-status

# 看清暂存内容后提交并上传
git commit -m "更新导航代码和验证指南"
git push origin main
```

若没有 Python Launcher，使用已安装 Python 3 的实际可执行文件。脚本要求 Python 3、Git、Git LFS，无额外 Python 库。Linux 上可运行 `python3 scripts/stage_workspace.py`。

只有 README 改动时可直接 `git add README.md`；完整快照统一用上述脚本。原 src.zip 含嵌套历史且与展开源码重复，保留本地但不上传；历史 RAG ZIP 会上传，最新运行代码以展开目录为准。

脚本排除 `.git`、build/install/log、缓存、编辑器配置、`.env*`（保留 .env.example）、`.pem/.key/.pyc`、根目录 results/sentry_maps/work。它不依赖嵌套 `.gitignore`，因此其原本忽略的地图也能完整上传。新增其他类型本机私密文件前，需同时更新根 `.gitignore` 和脚本排除规则；它不是通用秘密检测器。

## 机器人同步

先结束当前试验，再在机器人保存或提交自己的改动，然后：

```bash
cd ~/rrt_test
git pull --ff-only
git lfs pull
git lfs fsck
bash scripts/build_workspace.sh
```

如果 pull 报本地修改冲突或分叉，先审查差异，不使用 reset --hard 或强制 push 覆盖。上传脚本不会自动拉取、自动提交、自动推送或覆盖远端历史。

编译输出不上传，每台机器人自行构建。新建图和论文原始结果默认存到 HOME 下独立目录，按试验批次备份；确实需要纳入仓库时另选明确目录和 LFS 规则。

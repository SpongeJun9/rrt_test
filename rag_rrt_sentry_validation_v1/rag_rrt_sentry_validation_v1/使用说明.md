# RAG-RRT* 实物验证操作说明

## 1. 设备操作者需要做什么

你负责启动并操作原有机器人。我们提供规划程序和实验记录，不替换你的雷达驱动、定位、电控或原导航工程。

选一个已能稳定定位的室内场地即可，不必搭建论文仿真地图。先固定障碍布局，使用对应的原始二维地图和定位参考。保持实验期间场地稳定。PCD 由你现有定位系统加载，本包不另外处理 PCD。

把本压缩包解压到自己的一个独立目录，不要覆盖原工作区。它是可编译的 ROS 源码交付包，不是已在你的机器编译好的二进制。

## 2. 首次安装与编译

在终端中进入解压后的 `rag_rrt_sentry_validation_v1` 根目录。

已有 Humble、Nav2 和 colcon 的机器通常只需补齐 NumPy/YAML；依赖缺失时可用系统的软件管理方式安装。参考命令：

```bash
source /opt/ros/humble/setup.bash
sudo apt install python3-colcon-common-extensions python3-rosdep python3-numpy python3-yaml
rosdep install --from-paths src --ignore-src -r -y
bash scripts/build.sh
```

`rosdep` 需要机器已有初始化及本地规则；若提示未初始化或网络问题，保留完整输出，不要改动现有 ROS 发行版来解决。编译脚本使用系统 colcon/Python，不使用 Conda；不要在已有 RAG 测试工作区同时运行本包。

如果你的导航使用自行编译的 Nav2/消息定义，需要使用相同 underlay。例如把下面路径换成你真实的原工作区：

```bash
export SENTRY_UNDERLAY_SETUP="$HOME/dev_ws/install/setup.bash"
```

该变量可选；设置后 build/run/configure 脚本都会加载它。不要照抄一个不存在的路径。普通系统 Humble 无需设置。

## 3. 启动自己的导航系统

按你原来的步骤启动雷达、Point-LIO/定位、TF、地图、Nav2、速度变换、速度平滑和串口驱动。

- 使用实际室内场地对应的地图。
- 停稳车辆，关闭竞赛决策、自动目标、自瞄及底盘自旋，保留原有遥控接管和急停方式。
- `FollowPath.enable_rotation` 应在控制器**启动配置**中是 `false`。提供的代码中，这个字段没有完整的动态更新分支；仅执行 `ros2 param set ... false` 不能证明内部状态已经变更。若原启动配置为 true，修改原配置并按你的正常流程重启导航后再试。
- 确认 `base_footprint` 是车体平面中心，600×600 mm 包含实际突出部件；如果不一致，修改下节配置并选对应的中心 TF，不能套用默认尺寸。

本包不会帮你启动或关闭原系统，也不会刷固件。

## 4. 一次性接口和低速设置

配置文件是：

```text
src/rag_rrt_real_validation/config/site.yaml
```

默认话题/节点来自提供的源码，运行时会核对：

| 项目 | 默认值 |
|---|---|
| 原始二维地图 | `/map` |
| 里程计 | `/odometry` |
| 定位 TF | `map → base_footprint` |
| 路径执行 Action | `/follow_path` |
| 控制器节点/ID | `/controller_server` / `FollowPath` |
| Goal Checker | `general_goal_checker` |
| 输出速度/串口订阅 | `/cmd_vel`，`geometry_msgs/msg/Twist` |
| 全局/局部代价地图节点 | `/global_costmap/global_costmap`、`/local_costmap/local_costmap` |
| 实验最大平移速度 | 0.3 m/s |
| 车体尺寸、外扩余量 | 0.6×0.6 m，四周 0.05 m |

如果实际节点带命名空间或名称不同，只修改这份配置，不修改算法代码。尺寸/中心必须与你的车一致，默认值不是校准结果。程序使用更保守的方形栅格净空，所以部分较窄通道可能被判无解；不能为了跑通临时缩小车体或净空。

先只读检查：

```bash
bash scripts/run_trial.sh --check-only
```

默认旧配置速度高、robot_radius=0.2，首次可能显示 CHECK_FAIL，这不是程序编译失败。结果目录会保存读取的参数与拒绝原因。

停稳车辆、没有其他导航任务后，预览并应用实验设置：

```bash
bash scripts/configure_trial.sh
bash scripts/configure_trial.sh --apply
bash scripts/run_trial.sh --check-only
```

脚本降低控制器与速度平滑器的速度，设置覆盖车体和余量的矩形 footprint，并发一条 `/cmd_spin` 零值清除速度变换中的旋转偏置。下位机自旋仍由你按原系统方式关闭。

它修改**当前节点的运行参数**，不修改你的 YAML；重启原导航后需要重新应用。某个参数不支持动态修改时脚本会报错，可能前几项已生效，不能当作全部成功。此时按输出在原启动配置中修改对应值并重启，再进行只读检查。不要绕过执行检查。

`--config` 可指定另一份 site.yaml；run/configure 两个脚本要使用同一份文件。包不会静默调参，也不会自动恢复到旧的高速/小足迹设置。

## 5. 第一次只规划

在包根目录执行：

```bash
bash scripts/run_trial.sh --clicked-goal --method rag --seed 0
```

看到选点提示后，在原 RViz 中用 **Publish Point** 点击同一 map 坐标系内的可通行目标，默认最多等 120 秒。它与“2D Goal Pose”不同，不会向原导航发送目标。程序读取本次定位为起点，然后规划并保存结果，**默认不执行**。

可在 RViz 添加 Path 显示 `/rag_rrt/validation/reference_path`。该话题只用于显示；本包执行直接使用本次 RPC 返回路径，不订阅历史 Path。

如果你已经知道目标坐标，也可以：

```bash
bash scripts/run_trial.sh --goal-x X --goal-y Y --goal-yaw R --method rag --seed 0
```

将 X/Y/R 换成实际数值，单位 m/m/rad；这不是可以直接照抄的数值示例。路径不能以机器人当前位置为同一终点。规划失败会保留原因，不换种子重试。

## 6. 第一次完整执行

机器人停稳、原系统没有其他任务、只读检查已通过之后：

```bash
bash scripts/run_trial.sh --clicked-goal --method rag --seed 0 --execute
```

在 RViz 选择一条短而非零、绕行空间足够的任务。本包会：

1. 读取运行状态，核对低速、足迹、坐标和定位。
2. 用当前定位作为起点，请求一次规划。
3. 统一检查路径，保留所有原始折点重采样，不改变目标、不截断路径。
4. 发送一次 FollowPath，并记录状态、反馈、速度、定位估计轨迹。
5. 根据 Action、停止观察、估计终点误差及实际移动量给出结果。

地图变化、定位/里程计失效、检测到另一个导航目标、指令超速或超时会触发退出及取消流程。Ctrl+C 也会尝试取消自己的目标并发送零速度，等待 Action 终止和停止观察。**如果显示 STOP NOT CONFIRMED，请立即按原方法接管/急停**。程序依赖通信和定位，无法代替实车急停，也不能控制下位机的独立自旋逻辑。

不要打开多份本包并发运行；脚本对本机同一 ROS Domain 加了运行锁。执行前原竞赛决策必须关闭；程序检查几个常见导航 Action，但不能发现所有自定义下位机任务。

## 7. 三种方法怎么调用

```bash
bash scripts/run_trial.sh --clicked-goal --method rrt --seed 0 --execute
bash scripts/run_trial.sh --clicked-goal --method informed --seed 0 --execute
bash scripts/run_trial.sh --clicked-goal --method rag --seed 0 --execute
```

每条命令运行一个任务，完成后退出。每次开始前由你人工复位到相同任务起点附近，选择相同目标；不要把上一条路径终点直接当下一方法起点。本包记录实际起始定位偏差，后续评估公平性。

正式比较时最好保存目标坐标，改用 `--goal-x/--goal-y` 保持精确一致；预先冻结任务、速度、足迹、规划预算、Goal Checker 和种子。首次调试不混入正式统计。先三方法各一次验收，正式数量另定，不要求马上跑 210 次。

全向控制器关闭旋转且原 yaw 容差很宽，因此此版主要验证平面位置与路径执行，默认 yaw 评价阈值为 π；仍记录姿态误差，不宣称完成了目标朝向控制。若要验证朝向，需要另行适配旋转接口。

## 8. 输出和回传

默认输出在 `~/rag_rrt_real_results`，每次一个独立目录；终端会显示 RESULT 路径。失败和只规划任务也保留。

| 文件 | 内容 |
|---|---|
| launch.log | 本次启动、编译后运行或接口报错日志 |
| metadata.json | 状态、阶段、配置、方法/种子、实际起点、地图校验、时延及执行指标 |
| map.json | 本次地图快照 |
| navigation_parameters.json | 读取的真实导航参数 |
| planner_response.json | 本次规划结果及全部 PlannerMetrics；失败也保存 |
| reference_path.json | 送入控制器的完整重采样参考路径 |
| action_result.json | 完整 Action 结果；Humble 错误码不可用时另记 null |
| estimated_trajectory.csv | 正常定位 TF 估计轨迹 |
| estimated_trajectory.partial.csv | 执行过程中追加的部分轨迹，供异常退出排查 |
| feedback.json / last_command.json | Action 反馈和最终观察到的速度指令 |

并非每个阶段都会生成所有文件，例如只规划不会有 Action 结果。状态包括 CHECK_PASS/CHECK_FAIL、PLANNED_ONLY、EXECUTION_PASS、FAIL、INTERRUPTED。`EXECUTION_PASS` 不等于独立真值或碰撞真值验证。

回传指定的结果目录：

```bash
python3 scripts/pack_results.py "$HOME/rag_rrt_real_results"
```

生成的压缩包默认在主目录，原数据不删除。视频为可选辅助证据，请同时回传原始结果。此版本不自动录雷达 rosbag，避免高带宽存储影响首次验收；如正式阶段需要额外传感器录包，再统一冻结话题和 QoS。

## 9. 结果口径与当前限制

- 所有轨迹和终点误差来自正常定位估计，不是独立真值；无接触传感器/独立观测时，不据此报告“零碰撞”。
- RAG 先验生成计入规划总耗时；首次请求包含部分加载开销，各方法一致记录，不隐去。
- 单调墙钟用于请求与执行耗时，不启用仿真时间。
- 三方法共用保守的连续线段跨栅格检查与净空。这是实物部署中的统一地图检查变化，与旧 P3 检查口径不同，不直接合并旧碰撞检查统计或宣称算法核心改进。
- 算法源码保持收到版本，源码 SHA-256 清单可核对；改变的是外部地图检查、打包和运行流程。
- 当前依赖静态地图；地图外的新障碍和独立碰撞评价未由本包解决。正式采集前固定场地、地图和任务。
- 没有使用 Jetson 的必要；先使用原上位机。
- 此包未在助手环境完整编译 ROS，也没有实车结果。第一次编译/检查产生的报错可回传定位，不能把本地模拟测试理解为实车通过。

## 10. 常见问题

| 现象 | 检查方式 |
|---|---|
| 找不到 /odometry 或 TF | 修改 site.yaml 为实际话题/中心帧；先确认原导航正常 |
| 参数服务不存在 | 用 `ros2 node list` 确认节点及命名空间 |
| CHECK_FAIL：速度/足迹 | 运行 configure_trial，读取实际生效值；必要时改原配置并重启 |
| 停止状态不能确认 | 查看 last_command.json；检查 fake_vel 旋转偏置、里程计、定位稳定性和原自旋关闭状态 |
| 找不到算法 | 检查编译是否完整、是否 source 了本包 install；不用填写 /home/yanzu 路径 |
| 狭窄通道无解 | 对照实际车体、余量、地图分辨率和有效净空；不删除失败或随意缩小尺寸 |
| 发布目标后原车先动了 | 使用了 2D Goal Pose 或原决策仍运行；停止并改用 Publish Point |
| Action 成功但结果 FAIL | 查看估计终点误差、移动量和停止条件；不把 Action 状态直接等同实验通过 |

接口核对依据：[Humble FollowPath](https://github.com/ros-navigation/navigation2/blob/humble/nav2_msgs/action/FollowPath.action)、[Humble rclpy ActionClient](https://github.com/ros2/rclpy/blob/humble/rclpy/rclpy/action/client.py)、[Humble Costmap2DROS](https://github.com/ros-navigation/navigation2/blob/humble/nav2_costmap_2d/src/costmap_2d_ros.cpp)，以及此次提供的实车源码。

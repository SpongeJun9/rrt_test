# 整套实车系统启动与单次 RAG 验证

新增 full_stack.launch.py / scripts/run_full_stack.sh。它调用机器人原工作区已编译的驱动、定位、重定位、感知、控制及串口包，不复制这些包，也不启动比赛决策、实时 slam_toolbox 建图或导航行为树。

## 一次性准备

将本验证目录放到机器人 Linux 系统，原完整工作区必须已经编译可用。不要在原导航仍运行时重复启动本入口。

```bash
# 替换为机器人原工作区真实路径
export SENTRY_UNDERLAY_SETUP=/你的原工作区/install/setup.bash
cd /你的路径/rag_rrt_sentry_validation_v1
bash scripts/build.sh
```

地图 YAML、图像与重定位 PCD 必须是同一场地、同一地图坐标。启动前核对 src/rag_rrt_real_validation/config/site.yaml 的车体外廓和中心 TF；默认 0.6×0.6 m 加四周 0.05 m 只是预设，不是实车标定结果。串口沿用原 core_serial_config.yaml，可通过 serial_config 指定另一份。

## 一条命令启动

```bash
bash scripts/run_full_stack.sh world:=rmul2026
```

world 从原已安装 pb2025_nav_bringup 包的 map/reality/<world>.yaml 和 pcd/reality/<world>.pcd 选择。rmul2026 在提供源码中有同名文件，但是否适合当前场地需按实物选择；不匹配时使用：

```bash
bash scripts/run_full_stack.sh \
  map:=/实际场地/地图.yaml \
  prior_pcd_file:=/实际场地/重定位地图.pcd
```

可选参数：params_file:=原导航参数.yaml、serial_config:=串口参数.yaml、site_config:=试验设置.yaml、use_robot_state_pub:=false（仅当已有正确 TF 发布器时）、method:=rag_bpc_conn_init_rel_only、seed:=0、output_dir:=结果目录。本入口仅支持无命名空间的原实车接口，强制使用真实时间。

程序会同时启动：

- Livox 驱动、Point-LIO、small_gicp 重定位、地图服务器、机器人模型 TF。
- loam_interface、sensor_scan_generation、terrain_analysis、terrain_analysis_ext。
- Omni PID 控制器、速度平滑、fake_vel_transform、core_serial。
- RAG 后端、一次任务执行程序和专用 RViz。

为兼容原验证程序对全局代价地图的检查，保留 planner_server 的全局代价地图；没有启动 bt_navigator 或其他全局规划请求端，本次任务仅调用 RAG 后端一次，不调用 Theta*。

等待终端提示目标输入后，在弹出的 RViz 使用 2D Goal Pose 点击、拖动、释放。只接收第一个目标，规划一次、发送一次 FollowPath。后续点击不会改目标。完成/失败后整个启动组退出；新一轮重新运行同一命令。Ctrl+C 沿用验证程序取消逻辑，不能替代原遥控急停。

## 自动生成的试验参数

原导航配置不改写；每次在 ~/rag_rrt_real_results/stack_* 保存 navigation.yaml、site.yaml、inputs.yaml，子目录保存规划及执行结果。可复制和核对实际下发的配置。

生成配置限制平移速度、关闭控制器旋转和 fake_vel 的初始自旋、设置包含车体余量的矩形 footprint，并把速度平滑器各轴上限设为速度上限 / sqrt(2)，避免斜向速度超过标量限制。下位机独立的自旋行为不由上述参数控制，应在原电控模式中关闭。当前串口导航包只发送 x/y 平移。

Point-LIO 在此作为里程计运行，其内部局部地图仍服务于定位；这里关闭的是在线全局 SLAM 建图。障碍感知继续用于控制器碰撞检查，遇障失败退出而不重规划。

源码接口还有一项需在实车核对：机器人模型的 joint_state_publisher 订阅 serial/gimbal_joint_state，而当前 core_serial 源码未发布该关节反馈，只发布 odom_v → gimbal_link。此入口沿用原模型与串口，未虚构编码器反馈；若实车依赖额外关节反馈节点，需保留该节点并核对 base_footprint、gimbal_yaw、front_mid360 的实际 TF。机器人云台活动时不能把缺失反馈当作零角度标定结果。
